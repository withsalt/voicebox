# DTD 延迟归因与训练方案：全部评测项不弱于基线

证据截点：2026-10-19 09:27，Asia/Shanghai。本文执行的是分析与方案制定；未启动训练、改写训练脚本或替换部署模型。工作区另有 R30 正在训练，截至截点只有 epoch 0 的训练记录，尚无完整声学/E2E 结果，不计入已验证收益。

## 1. 结论与目标

下一步应优先修复训练监督冲突，让模型在真实说话开始时及时、连续地给出正确证据，再优化完整判定链的首次确认时间。不能继续依靠整体降低正例置信度换取较少误报，也不能用总体召回提升掩盖个别场景退化。

最新目标解释为：**所有评测质量项不回退是硬条件，在满足条件的候选中尽可能降低延迟**。这替代旧计划中“五个弱项必须同时严格改善”的要求；与基线持平可以通过该项，任何退化不能由其他项的进步抵消。单模型部署约束保持。

训练过程中的每个实验点不可能预先保证不回退；可以严格保证的是验收规则：不满足约束的候选不升级，继续保留基线。有限评测也不能证明所有未来真实场景永不回退。

基线固定为 2026-10-12 的 e147，ONNX SHA256：`3EB35D158CCAD47A072BFD57DBD99467E522F41A4D9FF414E4C6399F6245F156`。本次复核部署文件仍为该哈希。

## 3. 延迟原因：哪些已证实，哪些需要实验确认

### 3.1 已证实：同样能检出的案例也变慢，并非纯统计假象

E2E 按官方 `clusterId` 分组、组内取最大延迟、排除提前触发/缺失值，固定共同观测案例重新比较：

| 比较 | 共同成功 cluster | 基线 P95 | 候选 P95 | 配对延迟差中位数 | 变慢超过 200ms |
|---|---:|---:|---:|---:|---:|
| R23 vs e147 | 74 | 1475ms | 2426ms | +20ms | 11/74 |
| R28 vs e147 | 71 | 1490ms | 2460ms | +30ms | 11/71 |

R23 另恢复 3 个观测，延迟分别为 260、2952、5292ms，确实也抬高总体 P95；但固定原来的 74 个成功 cluster，P95 仍增加 951ms。不能把全部回退解释为“救回了慢案例”。

具体案例：

| 案例 | 基线 | R28 | 差值 |
|---|---:|---:|---:|
| 声学 synthetic-344 | 1132ms | 5452ms | +4320ms |
| 声学 synthetic-365 | 644ms | 1780ms | +1136ms |
| 声学 synthetic-389 | 792ms | 1384ms | +592ms |
| E2E wenet/Y0000004071_9q-UBOJCP2g | 380ms | 2780ms | +2400ms |
| E2E aishell3/SSB17820465 | 956ms | 2924ms | +1968ms |

声学共同观测 95 例中，R28 有 33 例变慢超过一个 16ms callback，没有一例快超过 16ms。这支持“部分难例被明显推迟”，而不是所有案例统一增加固定时延。16ms 只用于诊断分组，不是放宽验收的容差。

注意：这里声学共同观测子集的普通分位数不是官方声学分位数。官方声学报告将漏检/提前触发纳入右删失；官方 E2E 分位数仅统计可观测 cluster，并另报删失数。两者不可混用。

### 3.2 已证实：大部分新增等待发生在 heard 之前

逐原始正案例计算 `drainCompleteLatencyMs - heardLatencyMs`，不是把两个整体 P95 相减：

| 模型 | 有效配对案例数 | heard→drain 中位数 | P95 | 最大值 |
|---|---:|---:|---:|---:|
| 基线 | 79 | 10ms | 16ms | 16ms |
| R23 | 82 | 10ms | 16ms | 16ms |
| R28 | 80 | 10ms | 16ms | 16ms |

在这些回放结果中，几秒钟的新增拖延已经存在于“确认近端说话”时；设备清空缓冲不是该回退的主要来源。含房间拖尾的 audible-stop 与 drain 是不同指标，仍需保留验收。

部分 `stopLatencyMs` 比 heard 晚 3.9–9.6 秒，但对应 drain 仍仅晚 0–16ms，存在控制停止记录与首次停播时间不一致的现象。需要核查是否记录了后续 clear，不能将该字段直接解读成设备实际又播了数秒，也不能未经修复就豁免该指标。

### 3.3 已复现的监督冲突：缺少教师标签被当成“全程没人说话”

当前代码路径：

1. `enriched_dataset.standard_item` 在开启 `DTD_ANCHOR_TARGETS` 时，把默认 `anchor_target` 补为全零。
2. 只有 materialized 分支读取真实教师 sidecar 覆盖它；混合抽样另外三个分支的权重合计为 0.4+0.2+0.2=80%。这不是说 80% 帧都是正例，而是这些分支没有真实教师标签。
3. `train_dtd.run_training_epoch` 使用 `valid_mask` 计算全部帧的 anchor BCE，没有“此帧是否真的有教师标签”的 mask。R23/R28 的历史记录也证实 anchor loss 非零、权重为 0.5；但历史脚本快照/环境变量不完整，因此不能据当前代码精确分摊历史损失。

结果是：真实标签说“有人在说话”，额外的蒸馏标签却说“没有”。CPU 小实验直接调用当前数据构造及损失函数，复现了该冲突。仅考虑正例 BCE 权重 1.5 与零 anchor 权重 0.5 时：

`L(p) = -1.5 log(p) - 0.5 log(1-p)`，单独最优点为 `p=0.75`。

| 当前概率 | 正常正例监督的梯度 | 加入错误零 anchor 后 | 梯度下降效果 |
|---|---:|---:|---|
| 0.55 | -0.675 | -0.400 | 仍向上，但动力变弱 |
| 0.75 | -0.375 | ≈0 | 两种监督抵消 |
| 0.90 | -0.150 | +0.300 | 反而把正例分数往下压 |

这不是模型所有输出被硬封顶 0.75：其他损失、共享参数及真实教师标签仍会影响结果。但它是可复现、应先修复的训练目标冲突。多个慢例最终概率约 0.74–0.77，与该机制相符，不能据此宣布已经证明几秒延迟全部由它造成。

### 3.4 已证实的放大机制：过 0.55 不等于允许打断

当前实际链路：40ms 音频窗口、20ms hop → 3-hop 因果平滑 → 阈值 0.55 → AEC/回声证据融合 → 360ms 最近窗口评分 → 发布确认。

| 环节 | 实际规则 | 对延迟的含义 |
|---|---|---|
| 概率平滑 | 最近 3 帧，跨度 60ms | 瞬间高分不一定立即成为有效帧 |
| 声学证据融合 | 原始/平滑概率与回声、残差信号联合判定 | 过阈值仍可能被判为回声或缺乏证据 |
| 有效分数 | 有效帧 +20ms；拒绝帧按 0.35 或 1.0 倍扣分 | 一旦犹豫，先前积累会损失 |
| 最终确认 | 分数 ≥180ms；有效时长 ≥104.4ms；连续有效 ≥60ms | 需要持续的正确证据，不是偶发高分 |
| 回声和末尾要求 | 回声占比 ≤1/3；末尾 80ms 至少一半有效且最新帧有效 | 中途/末尾抖动会继续推迟 |
| 启播/路径变化 | 启播 guard、对齐/状态重置、路径变化 guard | 影响特定起点与难例；需逐帧追踪 |

这些窗口重叠，不能简单相加成“固定 600ms”。500ms 启播 guard 也不能机械加到所有 heard 延迟上：很多近端语音在启播后较晚才开始，eligible-onset 已考虑资格条件。

以无 preserved 支持的简化例子说明：概率约 0.75 时，归一化 modelSupport 约 0.719；若 echoSupport 为 0.4，融合分数约 `0.719×(1−0.85×0.4)=0.475`，达不到 0.50。概率过 0.55，却仍积不到有效时长。这解释了为什么单纯“过线稍早”不一定解决最终延迟。

synthetic-344 在 R28 中累计 166 次 near-end 观测仍等到 5452ms，最后 240ms 接受证据只留下 186ms 分数，并经历一次路径 guard、三代对齐。证明“模型曾说过有人”不能等同于“已经有足够连续可靠证据”。缺少全程轨迹，尚不能给回声否决、重置与模型低分分别分配具体毫秒。

### 3.5 已证实的目标错配，以及待验证的教师时序问题

- 现有 onset loss 加强起点后最多 360ms 的逐帧正例概率，未直接优化整条 C# 链的首次确认时间。
- 旧 event loss 奖励一个时段内的最大支持度，不等于越早首次确认越好；R23/R28 的 event/reset 权重都是 0。仅把旧 event loss 打开不能视为已设计好低延迟目标。
- trainer 的主选择分数为 AP + F1/低误报率召回的组合，不包含实际确认延迟或逐项不回退约束。帧级“优等生”可能是端到端慢模型。
- 决策蒸馏会在教师尚未越线但真实语音已开始的区间给零目标，与及时触发目标冲突。R30 已尝试修正 onset 标签；其记录声称教师有长尾迟触发，但本次未独立重放该时序抽样，不能把该统计当作已复核因果比例。
- R28 同时加强负例损失 0.15→0.40、难负流概率 0.5→0.8，误报改善而 P95 未改善。该方向主要解决误报，不能代替及时正例学习。两项同时改动也不能归因到单个旋钮。

### 3.6 尚不能断言“网络计算慢”，也不能忽略运行版本差异

基线/R23/R28 使用相同的 288×3 GRU、约 165.7 万参数和 92.7304 MMAC/s。声学整套 RTF 约 0.018–0.019，说明回放总体处理较快，但这不等于逐 hop P99 推理/排队都快。当前无同环境的逐帧耗时 profile；先测再决定是否缩小模型。

更重要：基线报告 commit 与 R23/R28 不同，后两者标为 dirty；核对 Assistant、DTD、Benchmark 三个 DLL，R23 与 R28 一致，均与基线留存哈希不同。源码中也有未提交的链路改动。**当前结果可证明候选评测比历史基线慢，不能把全部差值严格归因为训练权重变化。** 同一冻结 runtime 上重跑 e147 是下一阶段前置条件；历史基线标准继续保留，不因重跑而自动放宽。

## 4. 训练方案：先纠错，再优化确认时间

### 阶段 0：建立可信对照，修复训练与评测口径

交付条件：

1. 冻结 e147、候选 ONNX、runtime DLL、配置、数据 manifest/音频、ASR/TTS/VAD、CPU/GPU 后端及训练源码哈希；在同一运行环境上进行基线/候选配对回放。性能 profile 时不与训练并发争抢资源。若 runtime 改动导致基线自身回退，先独立处理，不能训练补偿后再宣称纯模型提升。
2. 增加 `anchor_valid_mask`/`has_teacher`：无教师项 mask=0，有教师项 mask=有效音频且时间对齐；padding、gap、重置无效帧不参与。不得用 0 代表缺失标签。
3. mask-only 对照保持原来的全 valid 帧分母，先仅移除错误项。若改用有教师帧数作为分母，20% 覆盖率会显著改变有效损失尺度，必须重新标定权重，不能与 mask 修复混成一个变量。记录每个来源的覆盖率、正例比例、损失和梯度范数。
4. 对齐教师/真值/40ms 窗与20ms hop的时间定义；从精确侧标读取 onset，教师未检出不能当可靠负例；保持真正远端单讲、起点之前和 reset/gap 区间保护。
5. 记录逐 hop：采样时间、真值/eligible onset、raw/smoothed p、AEC证据、融合score、accept/reject原因、累加器score/连续/末尾条件、对齐/guard/reset、排队与推理耗时、heard、首次clear、drain、audible-stop。得到“概率先晚”还是“概率已够但规则否决”的可归因轨迹。
6. 给缺教师正例、真负例、有教师正例、gap/reset/padding 分别做数值检查；无教师时 anchor 梯度必须精确为0；不改动实际判定规则。训练代理必须先与冻结 C# 回放对齐再用于选模。

### 阶段 1：小预算单变量实验

下面是待执行建议参数，不是已验证最优值。保持单模型、阈值0.55、180ms/360ms规则、AEC/ASR/TTS/VAD不变；不覆盖正在运行的R30目录。

| 试验 | 起点 | 唯一主要变量 | LR / epoch预算 | 用途 |
|---|---|---|---|---|
| C0 对照 | R23 e12 | 原配方 | 5e-5 / 3 | 为修复实验提供相同训练步数对照；不会升级 |
| C1 监督修复 | R23 e12 | 仅修 anchor mask，保持原分母 | 5e-5 / 3 | 验证错误零标签是否压低分数并推迟确认 |
| C2 保守分支 | e147 | 正确mask下的同类微调 | 1e-5 / 3 | 从基线保留能力出发寻找可行解；与C1差异不作单因素归因 |
| T 起点对齐 | 验证集表现更好的 C1/C2 | 仅改教师迟到区间的监督 | 保持所选分支LR / ≤5 | 真实起点后优先真值；其余可靠教师知识保留 |
| L 首次确认优化 | T或C1/C2中可行者 | 加入首次确认/长尾损失 | 保持所选分支LR / ≤5 | 在前述修复后仍慢时启用；不能直接复用旧event loss定义 |

统一起始参数：batch128，clip8s，seed43，40/20/20/20来源比例，12,000 examples/epoch，现有固定验证拆分，288维×3层，80频带，dropout0.1，weight decay2e-4，positive weight1.5，frontend冻结。C0/C1/C2采用 anchor0.5、onset0.1、hard-negative0.15、hard-far-only0.5，event/reset0；起点对齐试验也先保持 onset0.1，不同时改成0.3。每轮保存checkpoint并按真实链验证。

验证集应按说话人/原始录音/device-session/RIR来源隔离；既有测试集已多轮用于诊断，需增加从未用于选模的来源隔离最终留出集。评测中的具体失败音频只能用于诊断和验收，不能复制进训练或定向记忆其ID。

### 阶段 2：让训练目标明确奖励“尽早可靠确认”

新损失的目标是**在真值起点之后，越早满足实际判定链越好**：

- 正例：对起点到首次可靠确认期间的“尚未确认”持续计费；对最慢的一组再增加权重。漏检按完整观察窗持续计费并另罚漏检，不允许靠删除慢/漏检事件优化P95。
- 基线保留：在独立训练/验证数据上，保护 e147 已正确检出、已正确拒绝的行为；对基线已及时确认的正例，惩罚晚于其确认时间；对可靠真负例，惩罚任何提前确认。
- 真值优先：教师错判/迟判的正例不能继续当负约束；教师保护按标签可靠性与来源隔离，而不是所有帧一刀切拉近。
- 因果一致：代理包含3帧平滑、score扣减、连续60ms、末尾80ms、回声占比、RMS门、reset/gap/guard。声学profile会随模型输出更新，不能固定复用基线profile冒充完整候选回放。
- 实施方式：训练用可导代理，验收仍用未改动的C#完整回放。若代理不能复现实际首次确认，先修代理，不增加训练轮次掩盖误差。新loss可从归一化后权重0.05试起，但必须先检查梯度量级，避免压过主BCE/负例保护；这是待验证试点值。

训练素材优先覆盖弱近端/强回声（SER≤0）、非线性回声、近端噪声、轻声起句、短促插话、移动/重置/参考缺口。这里是失败模式指导的数据类别，尚不是已完成的声学因素因果隔离。正例与相同条件的纯回声负例成对生成，保留80%原始抽样、最多20%替换为独立难例作为起始建议；不全局继续提高负例占比。

### 阶段 3：先选可行模型，再选最快模型

每个checkpoint先检查全指标约束。仅在满足约束的集合内，按 E2E heard P95 → drain P95 → 声学P95 → P50 的顺序择优；AP、训练loss只用于诊断。不能使用加权总分让某项进步抵消另一项回退。

先在验证集比较C0/C1/C2。若三轮内明确退化且无改善趋势，停止该分支，不盲目延长。较有希望配方在 seed43 之外以47、59复验；最终checkpoint和阈值先冻结，再运行正式完整benchmark。尚无可行候选时，允许保留研究检查点，但部署基线不动。

R30当前同时修改教师起点标签和onset权重0.1→0.3，又沿用当前anchor路径。它可提供探索结果，不能独立证明哪项原因成立，也不能替代C1的mask修复对照。等待其完整结果后按同一硬门验收；本次没有改动其作业。

### 阶段 4：有实测瓶颈再压计算量

先记录CPU目标设备单hop推理/排队P50、P95、P99、分配与reset冷启动耗时。若耗时已远小于20ms hop且没有积压，缩模型对秒级确认尾延迟的收益有限，应优先前述监督和时序问题。若有可观测计算瓶颈，再单独试小学生模型/蒸馏或推理优化，并重过全部质量与时延门；不把压缩与语义训练改动混在一起。

## 5. “每项不弱于基线”的具体验收

1. 全体声学/E2E整体指标和每个原有可比较切片逐项比较：召回、precision/specificity、置信界、误报率及上界、各延迟分位数、删失、CER、exact-match、空识别、过早触发、执行错误等全部纳入。空值、缺行、样本数变少不是通过。duck/resume在当前停止策略下的跟踪项也需保持定义、不得静默删除。
2. 逐案例/cluster：不新增FP/FN/early，不把原有成功变成漏检；基线成功的配对确认延迟另列回归清单，不能藏在总体P95之后。按本次严格目标，确定性的配对延迟回退也阻止升级。
3. 标识/暴露量、版本、wallTime等元数据不机械判断“越小越好”。例如`negativeExposureHours`反映统计暴露量，应检查分母及停止规则，而不是将暴露变大自动判成质量退化；误报数、官方率及上界仍须通过。
4. 对受运行随机性影响的ASR/停止相关指标，使用同配置、固定种子、交替顺序的至少3组基线/候选配对复测。不可沿用旧“噪声豁免”名单跳过。若结果波动或置信不足，标记“尚未证明不弱于”，不升级，也不擅自设允许劣化容差。
5. 按独立来源cluster做统计，而不是把同源变体当独立样本。多项逐个95%区间不等于整体95%保证；正式统计门需预注册同时区间或多重比较校正。相等的稳定结果可按实际观测不回退验收，但不能宣称无限泛化保证。
6. E2E负样本目前只约12.2分钟，单个误报约影响4.93次/小时；扩大独立负样本压力集验证稳定性，不能只凭2比6个误报就宣布生产环境误报问题彻底解决。
7. 先恢复至本报告所有基线阈值，再把声学P95≤700ms、E2E heard P95≤1000ms作为进阶目标；这两个值来自现有产品门，不能承诺固定guard与数据条件下一轮必达。
