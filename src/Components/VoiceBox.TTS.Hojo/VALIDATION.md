# Hojo 验证记录

## 40M V2 FP16 CPU 实验

2026-11-16：将原版部署包的三个 ONNX 图转换为内部 FP16、保持 FP32 输入/输出，在 Core 3 100U 的四个 E 核上用现有 C# benchmark 做 FP32 / FP16 / FP16 / FP32 对照，共 16 次正式合成成功。2 线程、40 帧块下，FP32 / FP16 加权 RTF 为 0.969 / 1.090，首块中位数 856 / 903ms，峰值 RSS 693.9 / 697.0MiB。FP16 未加速，仅使部署包由 325.4MiB 缩至 181.8MiB。ORT profile 证实主要矩阵与卷积运算仍为 FP32，增加了浮点 Cast。

固定 token 和解码输入的数值检查完成，实验包可由现有库直接加载，未修改默认部署方案。[完整实验报告、数值结果与复现步骤](../../../scripts/hojo-tts-prepare/FP16-EXPERIMENT.md)。

## 功能与数值验证

Windows x64、AMD Ryzen 9 9950X、.NET 10、ONNX Runtime 1.31.1：**23 项测试通过，0 失败，0 跳过**。未配置真实模型及 golden 环境变量时，18 项普通测试运行，5 项真实模型测试明确跳过。

- 服务契约：整句和流式 PCM 一致、成功仅一个终止标记、空输入、不可用参数与生成上限。
- 生命周期：提前退出枚举、背压、排队取消、容量溢出、推理异常后恢复、初始化失败重试、初始化中释放、重复并发释放；60 次并发提前中断验证单实例始终只有一个推理且容量恢复。
- 配置与 DI：请求及服务配置快照、默认/命名实例注册与共享。
- 数值路径：解析形式验证 ISTFT；采样惩罚、极小正数惩罚不溢出、top-k、非有限数拒绝；中文数字和拼音标签规范化。
- Hugging Face 官方 tokenizer：14 组中英文、数字、空白、Unicode、拼音标签、added-token 输入对照。
- LM：同平台同版本 ORT 下，独立 Python 官方实现与 C# 的短句贪心音频 token 完全一致，512 维 hidden 每项绝对差小于 0.0002。
- 分块解码：3 种句长 × 5/20/40/100 帧分块，与官方整句解码相比长度相同，SNR > 80dB，最大采样误差 < 0.0002。
- 真实推理：四种中文固定音色、同 seed 整句/流式一致、取消与生成上限后再次请求成功。

Python 参考代码来自 Hojo 官方提交 `3b89b2391dfd3b03438e4fe6bc7d72c0f8b4f989`。LM 严格对照数据必须在测试 CPU 上使用相同 ORT 版本生成。旧版本 Linux INT8 golden 与 Windows ORT 1.31.1 的 hidden 存在差异；匹配平台和版本后通过，不能将跨版本 INT8 的逐 token 一致性当作保证。`create_golden.py` 记录平台、依赖版本及模型哈希。

## 四个低功耗核心的实测

远程机器为 **Intel Core 3 100U**，Ubuntu 26.04.1、物理内存 16GB、.NET 10.0.15、ORT 1.31.1。用 `taskset -c 4-7` 仅允许四个 E 核运行；这不等同于任意四核 CPU，也没有将主机内存限制为 8GB。TTS 进程内存实测远低于 8GB，未包含 ASR、LLM 或其他应用。

每种线程配置均为独立进程，先加载和预热，再测短确认、天气、日期数字、长回答四类文本，每类三轮，seed 为 42/43/44。每组追加 40 次短句/提前中断请求。合计 **24 次正式合成 + 80 次连续请求**，无失败。

|---|---:|---:|
| 常规 PCM 块 | 800ms | 800ms |
| 首块 PCM 中位数 | 527ms | 454ms |
| 首块 PCM 全部样本范围 | 463–785ms | 423–505ms |
| 总生成时间 / 总音频时长（加权 RTF） | 0.681 | 0.579 |
| 最慢单次 RTF | 0.833 | 0.647 |

| 40 次连续请求 RSS 起点 → 终点 | 650.9 → 617.9MiB | 581.5 → 605.3MiB |

## 整体代码审查

已逐文件检查新增库、模型准备、测试、benchmark 和 Demo，重点覆盖原生资源所有权、取消/释放竞争、队列边界、KV 与 hidden 对齐、分块前瞻、尾块刷新、参数护栏、数值异常与错误传播。设计保持服务编排、内部推理接口和各数值阶段的直接组合，未引入通用流程框架。

审查与实测中修正并验证：

1. 关闭闲置 ORT 线程自旋，避免三个顺序会话争抢四个 E 核。
2. tokenizer 保持模型序列化 regex 的实际语义，并处理 Unicode `İ` 小写展开。
3. 采样惩罚使用 double 中间值，避免极小正数惩罚引起浮点溢出。
4. 提前终止枚举、初始化中释放及慢消费都等待生产者/原生推理退出，再释放资源；不通过超时强行释放仍在使用的原生对象。
5. Demo 简化为文本输入与流式播放，保留播放背压、取消和尾部音频等待。
6. 严格 LM 对照数据绑定相同 ORT/CPU 环境，避免将运行库量化内核差异误判为 C# 状态错误。
7. 加权采样使用严格区间边界，避免随机值为零时选中概率已下溢为零的 token；播放错误保留原始原因，退出时停止播放器。

本轮验证范围内未留下已知阻断问题；这不是对任意模型包、硬件和负载“绝对无 bug”的承诺。运行时支持已验证的 Hojo 80M 和 40M V2 架构，完整输入文本生成流式音频；不支持运行时音色克隆或单句内持续追加文本。
